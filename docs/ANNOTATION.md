# 人工复核与六视图

原始 MVTec AD、VisA、KSDD2 已有缺陷标注，真实数据不重画。新增合成缺陷的实际 M 不会自动继承真实图标签；FLUX 的编辑支持域 R 也不能代替 M。

每个核心只确定一次 M。三种条件的异常视图共享 M，三张正常视图使用零标签。G 初稿由 M 膨胀获得，必要上下文可人工扩展；Q 和 alpha 由程序确定。修改 M/G 后必须整体重建一个新版本，原审核不能继续使用。

当前自动初稿是 R 内 RGB 残差候选。它是复核辅助，无法可靠区分微弱缺陷与正常生成变化；尤其细裂纹、低对比度、颜色变化必须查看局部放大。先在开发 40 组实测初稿修正率，未验证前不要估计人工完全只需点击通过。

## 操作

1. 正常父图 ROI 只需标定可编辑正常表面，可以复用同产品已验证规则、由自动工具产生初稿后确认。一个父图 ROI 复用多个核心尝试，不是每次扩散重新标。
2. 新缺陷生成后运行 `propose_annotation.py`，查看正常原图与原生异常，修正 `M_proposal.png` 为单通道 PNG（0 为背景、255 为异常）。可以使用熟悉的标注软件。
3. `build_crossed.py` 导出最终组六视图、M/G/Q、保护区联系图；自动检查机器不变量。
4. `export_review.py` 导出离线网页。每项判断默认未回答，不显示分割器预测。打开 native normal/defect 和联系图，必要时查看原分辨率。
5. 填写 reviewer、主动审核秒数、每条件五项判断和总体决定，下载 JSONL。不同审核者分别保存，合并后导入 `audit_controls.py`。

五项判断：实际 M 准确、正常状态有效、缺陷与必要证据保留、边界自然、外围编辑确实有效。原始条件的最后一项不适用。人工不能覆盖程序不变量错误。

## 审核政策

- 训练池：一人全量审核；按产品及 group ID 的固定哈希抽约 20% 做第二人独立审核。
- 诊断集：两人独立审核全部组。
- 已修正样本需第二人审核。拒绝／不确定／分歧保留记录，经修订形成新版本后重新审核。
- 第二人抽检的确定早于训练分数，与方法是否受益无关；小样本中实际比例可能偏离 20%，报告真实数量。
- 不成组样本统一不进入本实现的合成训练池，各内部方法共享接受清单。

按 4,800 组、每次 30–60 秒估计，一人全审约 40–80 人时；加 20% 第二审核约 48–96 人时，另计修正、ROI、诊断集及工具准备。这只是工作量假设，先记录开发 40 组的审核中位数、P95、修正率／耗时、拒绝率。不能将同核心六张图算成六次独立画掩码。

## 记录形式

每条审核记录绑定 `group_id + content_sha256 + reviewer`。候选图片、原语、mask、G、Q、alpha 和几何元数据的版本变化都会使旧审核失效。人工名字是可追溯记录，不是密码学身份认证；第二审核仍需团队按流程真实执行。
